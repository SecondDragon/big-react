⚛️ ReactSymbols.ts 实战

// 能力检测 — 前置条件
const supportSymbol = typeof Symbol === 'function' && Symbol.for;

// 所有内部类型：Symbol✨ + 魔数📉 双模式
export const REACT_ELEMENT_TYPE = supportSymbol
    ? Symbol.for('react.element')
    : 0xeac7;

export const REACT_FRAGMENT_TYPE = supportSymbol
    ? Symbol.for('react.fragment')
    : 0xeaca;
💡 核心设计原则： Symbol.for('react.element') 保证跨包唯一，0xeac7 是降级方案。 这种双模式 = 渐进增强（优先现代特性，退路给老旧环境）。

⚠️ 常见误区

❌ 误区 1：认为 Symbol 是私有属性
Symbol 键不会被 for...in 遍历，但可以通过 Object.getOwnPropertySymbols() 获取到。
真正的私有机制请用 #privateField（ES2022 class fields）。
❌ 误区 2：Symbol() 跨模块一样
Symbol('react.element') 在模块 A 和模块 B 中是两个不同的值。
✅ 用 Symbol.for('react.element') 才能跨模块共享。
❌ 误区 3：Symbol 不能做对象键
恰恰相反，obj[sym] = value 是 Symbol 最重要的用途之一。
📌 记住：Symbol 不是加密工具，不是私有字段，而是一个 「绝不重复的 ID 生成器」。

🧠 心智模型

把 Symbol 想象成「防伪标签」🔏：

  • Symbol() = 每次从机器里吐出一张全新的防伪码，世界上不会有第二张一样的
  • Symbol('desc') = 带批注的防伪码（批注不影响唯一性）
  • Symbol.for('key') = 在公安部备案的防伪码，全国（全局）统一可查
  • 用在对象键上 = 给你的对象贴上一个不能被意外覆盖的属性
  • React 用它 = 在每棵虚拟 DOM 节点上贴不可伪造的「类型标签」
